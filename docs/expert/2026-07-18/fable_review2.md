我把这个问题从头重推了一遍,找到了一个我认为整个专家链条都擦肩而过的组合:把"132-state 线性递推"升级成 pair 版本,并在中点做一次"对角拼接"。它的关键性质是:曾经杀死 reverse-gluing 的 symbol
  对齐问题,在这个坐标系里不存在。下面先给结构,再给为什么它和已否决的每条路线都不同,最后给门禁计划。
    重新推导:N(C) 的逐 box 全局 pair-DP
     
  把网格按 stack 分解后,已验证的目标是 N = Σ_G F(G)²,其中 G 等价于 6 个 balanced cut 的序列 (A₁,…,A₆)(A_b ⊆ 12 个符号,|A_b|=6,即 box b 里哪 6 个符号在上行),而
     
  F(G) = # { 每个 box b 一对双射 (f_b: 颜色→A_b, g_b: 颜色→Ā_b) :
             每个符号跨 6 个 box 收到的颜色两两不同 }

  "颜色"= stack 的 6 列。逐 box(而非逐 symbol)推进时,一个决定性的事实成立:box 内的全部结构(cut、两侧双射)在本阶段内完全闭合,跨阶段传递的约束只有"每符号已用颜色集"。所以:

  - 单 copy 的 DP 状态 = 每个符号的已用颜色集 P(s) ⊆ [6],且全局求和(对所有 cut 求和)下,状态相同的符号可交换 → 状态坍缩为 P-类型的计数向量。这正是 2026-07-15 那个 132-state histogram 递推——它对、它快,只是它算的是线性量 Σ wF,当时因"问题少写了平方"被整体搁置。
  - 平方的正确做法不是换 symbol 序(7-17 的 connectivity 路线,状态要带 path-pairing,C=5 第 3 个符号就 83,776 态、转移 (6!)²),而是在同一 box 序上跑双份:两个 copy 共享每个 box 的 cut(copy 2 侧翻),颜色组独立。Pair 状态 = 每符号 (P₁(s), P₂(s))
  的联合类型计数向量,类型空间 ≤ C(6,k)²,总质量 12,带每色边际约束(第 k 层每色恰被 2k 个符号用过)。

  Symbol 序需要 path-pairing 状态,是因为一个符号"插到一半"时 band 内部结构悬空;box 序下没有任何东西悬空。处理顺序本身就是压缩。

  中点拼接是对角的——alignment 问题消失

  6 个 box 拆成前 3 + 后 3。左半边算到第 3 层得到 Ŷ[a](a = pair-类型计数向量,系数 = 该状态的带标号左半对象数),右半边按 box 反演对称就是同一个对象。一个完整对象合法 ⟺ 两半各自合法 + 每符号在两个 copy 里前后颜色集互补。互补只依赖类型函数,于是拼接严格等于        

  N(6) = Σ_a  Ŷ[a] · Ŷ[ā] / N(a) ,   N(a) = 12!/Π_t a_t! ,  ā = 类型逐项取补

  (常数归一由小 C 门禁钉死。)这是一个排序-归并式的对角双线性型——没有 contingency table,没有 double coset,没有 15,360-leaf 的 join kernel。Reverse-gluing 死在对齐,是因为它的状态是几何配置类(mask
  结构),拼接必须重新对齐几何;这里状态只携带已用颜色类型,全部几何都已在半边内部被求和掉。付出的代价很明确:此路线直接产出 N(6) 总量,不产出 63,199 个逐类 F 值——它是 Pettersen 式的全局方法,不是逐类证书方法。

  门禁计划(全部有界,含 kill 条件)

  1. C=2、C=3 精确复现(预期毫秒级):钉死拼接归一常数与侧翻约定。实现基底可直接取 docs/expert/2026-07-15/global_linear_histogram_dp.cpp 的单 copy 核心做 pair 化。
  2. C=4、C=5 全量:复现 N(4)、N(5),并记录每层 pair 状态数与每态转移开销——给出增长曲线。C=5 奇数 box 用 2+3 拼接,顺带验证不对称拼接的公式。
  3. C=6 只跑第 1、2 层 + 第 3 层的状态计数(可只数不存值),加转移成本外推。不做完整 C=6 求和。
  4. Kill 条件:任一小 C 门禁失配(数学缺陷);或 C=6 第 3 层商后状态数 > ~10⁹ / 转移总操作外推 > ~10¹³(工程死刑)。死了就按既定政策回落——且如果 box 序都爆,symbol 序的 double-permanent 大概率更爆,这个负结果同样有决策价值。

  风险里最大的一个是概念性的:如果实测发现 pair 状态在共享 cut 下强关联到接近单类 future-twin 的 frontier 规模(9.6M→221M 那种增长),说明我低估了联合类型空间,路线止损。第二个是我可能重蹈"其实等价于某条已试路线"——第 2 步的逐层状态数与文档中
  connectivity/future-twin 的已知序列直接对比即可判别,不靠嘴。

  我的建议:这个实验排到 double-permanent 之前——它更便宜(几天)、gate 更硬(每步都是精确复现已知值)、而且无论生死都直接更新"全局收缩是否可能"这个最高价值未知量。
